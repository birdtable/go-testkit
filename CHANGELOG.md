## v0.3.1 - 2026-11-25

A docs release, for the repository going public. No name is added, removed or moved, and no signature changes, in any of the three modules: apidiff finds no change since v0.3.0, contain/v0.1.0 and taskfile/v0.1.0 on darwin, linux or windows. contain/v0.1.1 and taskfile/v0.1.1 are tagged at the same commit, for their docs and comments alone. No go.mod require changes in any module: the root imports the standard library only, contain requires go-testkit v0.2.0 and libcap/cap v1.2.78, and taskfile requires go.yaml.in/yaml/v3 v3.0.6 and mvdan.cc/sh/v3 v3.14.1, as at their last tags. The tagged tree is 5,234 non-test Go lines outside `internal/` (`task size`), at its ceiling of 5,234, up 24 from v0.3.0's 5,210, all doc lines: the root 3,800 (up 15), contain 945 (up 5) and taskfile 489 (up 4). The release checks ran on macOS (arm64), Linux (amd64) and Windows (amd64).

### For a v0.3.0 caller

Nothing changes for a test: every name gives what it gave. A test that matched the text of `Build`'s refusal of a package that starts with `-`, up to the issue it named, matches the new text below.

### Changed
* docs: the README is written for a reader outside the project: what testkit is for, how to install it, a quick start the tests compile, what each package and module does, what each is built on, the systems a release is tested on and what each refuses by name, and how to report an issue. `SECURITY.md` says a vulnerability is reported privately, through GitHub's private vulnerability reporting, and `CONTRIBUTING.md` says how to run the tests and send a change. Each package's doc, and the README of `contain` and of `taskfile`, says what it is built on, what it adds and what the caller configures. The calls that hand out the temp folder (`Main`, `Isolate`, `HoldRead`, `Binary.Path`, `ShortDir`) say that on macOS it is named as made, under `/var` and not `/private/var`, the known limitation v0.3.0's notes list. No comment cites an issue or a ruling.
* `Build`'s refusal of a package that starts with `-` reads "testkit: Build refuses a package that starts with -, which go build would read as a flag: " and the package. It named an issue before the colon, which a reader could not open; a test that matched that text matches the refusal's own words.
* build: the push tier is judged by its CPU time, under hatch v0.6.0, so a busy host does not fail it on wall time. Each module's `api/proved.txt` is gone: the systems a release was tested on are in its notes. No exported name, no behaviour of a call and no go.mod require changes.

## v0.3.0 - 2026-11-22
### Added
* `Interrupted(ctx)` gives a child of `RerunInterrupted` a context that ends at the interrupt, and its stop. It installs the handler and only then writes `Ready`'s line, so the parent's interrupt never comes before the handler and ends the child by the default action. Outside a child of `Rerun` it returns `ctx` and a stop that does nothing, installs no handler and writes nothing. Its error is `Ready`'s, and then it leaves no handler. `Ready` stays for a child that catches more than the interrupt.
### Fixed
* `cmd/apigate` refuses a name `api/marks.txt` lists whose `go doc` prints a line holding `Experimental`, and names the `api/marks.txt` line and that doc line. Listing a name marks it as not experimental, so the doc and the list disagreed, and v0.2.0's gate passed it.

### Known limitations
* Added 2026-11-22, after the tag: on macOS the temp folder `Main` and `Isolate` make, and so `t.TempDir`, `os.TempDir`, `TMPDIR`, `HOME`, `HoldRead`'s path and `Binary.Path`, sits behind the `/var` -> `/private/var` link and is named as made, under `/var/folders`, while a path read back by `filepath.EvalSymlinks` or `os.Getwd` is under `/private/var/folders`; `ShortDir`'s `/tmp` reads back as `/private/tmp` the same way. The two spellings differ as strings, so a test that compares a path it was given with one read back resolves its own with `filepath.EvalSymlinks` first. Neither v0.2.0's notes nor v0.3.0's said so. The kit keeps answering the spelling Go's `t.TempDir` and `os.MkdirTemp` give, and each of those calls' docs now says which spelling it answers.

## v0.2.0 - 2026-11-21
### Changed
* The module path is `github.com/birdtable/go-testkit`, as the repository is go-testkit, and the other two modules are `github.com/birdtable/go-testkit/contain` and `github.com/birdtable/go-testkit/taskfile`. An import changes its path alone: the package is still `testkit`, so no name in a test changes. v0.1.0 stays at the old path, `github.com/birdtable/testkit`, and is not to be pinned: its go.mod declares a module that go-testkit is not. Pin v0.2.0.
* `contain` requires go-testkit v0.2.0, and its first tag is `contain/v0.1.0`, at the new path. v0.1.0's notes named that tag, and it was never made at the old path. `taskfile`'s first tag is `taskfile/v0.1.0`.
### Added
* `github.com/birdtable/go-testkit/taskfile`, a module of its own, holds a repository's Taskfile.yml to Go in a test. `taskfile.Check` fails the test for each command that runs in shell what Go should do: a shell utility such as `grep`, `sed` or `tar`, a pipe, a redirection to or from a file, a `for` loop in shell, and the rest its README lists. A command the repository keeps in shell is a line of its `taskfile-exceptions.txt`, with the reason. It requires `go.yaml.in/yaml/v3` and `mvdan.cc/sh/v3`. testkit's own Taskfile.yml passes it in the commit tier.
* `cmd/apigate`, the API gate of one module, which a library's `task api` runs as `go run github.com/birdtable/go-testkit/cmd/apigate`. Three checks run from one host for darwin, linux and windows: the systems differ only as `api/systems.txt` says, the incompatible changes since the module's last tag are the lines of `api/breaks/<version>.txt`, and `go doc` finds each name `api/marks.txt` marks. `-dir` names a module in a folder of its own, held to its own `<folder>/v*` tags. Only git's own answer that there is no tag lets the tag check pass; any other failure of `git describe`, and a shallow clone, is red. The root and taskfile run it.
* Each module is built, vetted and linted on aix/ppc64, illumos/amd64 and solaris/amd64 as well, so a library that lints its tests there builds against go-testkit. No test runs there. `HoldRead` skips its test there with `NoHold`, and never fails it: Go's syscall package has no `Mkfifo` on those systems.

## v0.1.0 - 2026-11-21
### Added
* testkit, the test helpers the birdtable libraries share, as a module of its own. It was go-proc's `testenv` package, and go-proc v0.12.0 drops that package and takes testkit instead.
* `Main` runs a package's tests in a folder testkit makes. The tests keep only the environment names testkit lists, and the home variables, `t.TempDir` and git's configuration point into that folder. A child started through `Clean`, or with `Main`'s environment, sees none of the person's home, git or tool settings, go env file, or a token or a hook's variables the run was started with.
* Checks a test calls: `NoLeaks` fails a run that leaks a goroutine. `NoOpenFiles` reports each file and folder still open under the test's folder on Linux and macOS. On Windows it reports nothing, and the removal of the test's folder is the check there.
* Helpers: `GoOffline`, an option of `Main`, makes every go a test starts fetch no module and no toolchain. `GitPath` gives the host's git as an absolute path. `Link` and `Links` skip with `NoLinks` where the system refuses a link. `Rerun` runs a test again in a child that ends by itself if its parent is gone.
* `testkit/fake`: a stand-in program a test places and starts as a child, which does its steps the same on every system.
* `testkit/contain`, a module of its own, tagged `contain/v0.1.0`, which runs a package's tests contained. On Linux they run in their own user and PID namespaces, as a child of an init that reaps what they orphan, holding no capability in any set, except the mount capability of that namespace where `ContainMounts` keeps it. On Windows they run in a Job Object that ends their tree when it closes. Elsewhere, and where the system refuses, `Contained` skips a test with the reason.
* Requirements: the root module needs the standard library alone. `contain` requires `kernel.org/pub/linux/libs/security/libcap/cap` and `psx` v1.2.78, and testkit v0.1.0.
