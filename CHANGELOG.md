## v0.7.0 - 2026-11-26

One check is added to `canary`: `(*Set).Zip`, which reads each entry of a zip archive, its name, its comment and its bytes, and the archive's comment, so a support bundle a program writes is checked, with `CheckZip` beside it as its check's name. `canary` also closes four gaps: a line a check gives holds no run of 16 bytes or more of a planted value, where before only whole values and encodings were replaced; Files reads each link's target as text, and each Windows junction's; a read that ends short fails a check, where it was taken for the end; and Own's doc gives how often its quarter rule refuses a random hex key. No name is removed or moved, and no signature changes: the API check finds no break since v0.6.0. Every name added is experimental, as every name of the module is. `canary` still imports the standard library only, `archive/zip` among it, and the root's go.mod still requires nothing. contain stays at contain/v0.1.3 and taskfile at taskfile/v0.1.2: nothing in either module has changed since v0.6.0, and since contain/v0.1.3 contain's api/systems.txt and api/marks.txt change in their comments alone. The tagged tree is 7,519 non-test Go lines outside `internal/` (`task size`), at its ceiling of 7,519, up 196 from v0.6.0's 7,323 (2.7%), all in `canary`, now 738: 62 for Zip, 62 for the redaction of runs and the read of a link's target, and 72 for five fixes before the tag: a read that ends short (16), an encoding under 16 bytes (20), the zip comments (21), a junction's target (8) and the archive Zip refuses (7). The full release checks ran on macOS (arm64) at the tagged commit; vet and the tests, with the race detector, ran on Linux, macOS and Windows at the tagged commit in CI. No full release checks ran on Linux or Windows for this release.

### For a v0.6.0 caller

A test that passed at v0.6.0 can fail at v0.7.0 in three cases: Files now gives a hit for a link or a Windows junction under the folder whose target's text holds a planted value, where it gave none, and still follows neither; a link under the folder that it cannot read, as one removed after the walk, fails the test, as a file it cannot read already did; and a check whose reader ends with an error other than io.EOF fails the test, io.ErrUnexpectedEOF among them, as a gzip stream cut short gives through Reader, where it took that error for the end and passed what it had read. A line a check gives shows every run of 16 bytes or more of a value as <name>, where it showed a run that was no whole value or encoding, and still shows a whole encoding shorter than that as <name>, as v0.6.0 did. A test that wants a zip archive's entries checked calls Zip on it; Files still reads the archive as raw bytes. A test that draws its key at random each run and plants it with Own is refused by the quarter rule in about one run in 574, so it should plant a fixed value, or one New makes, as Own's doc now says.

### Added
* canary: `(*Set).Zip(path)` checks each entry of the zip archive at path, a support bundle among them: each entry's name, a hit there at `InPath`, as `Files` searches a path, and each entry's bytes, Stored or Deflate, through the same chunked read as `Reader`, so its memory is one chunk whatever an entry's size. A value in a folder of an entry's name is a hit at each entry under it, where `Files` counts it once, at the folder. It reads the archive's comment too, the place "<path> (comment)", and each entry's comment, "<path>!<name> (comment)", at the offset in the comment; it does not read an entry's extra fields, nor any bytes of the file outside the entries and the comments, which `Files` on the archive's folder reads raw. A hit's place is the archive's path, `!` and the entry's name, each value in it as `<name>`, with `CheckZip` as its check, the byte offset in the entry and the encoding. A corrupt archive, one `archive/zip` cannot open, an entry name it refuses as insecure under GODEBUG=zipinsecurepath=0 among them, and an entry it cannot read, a checksum that does not match, a compression method it does not know or bytes that end before its header says among them, fail the test; an archive it refuses is closed. It does not open a zip archive inside an entry, which it reads as that entry's bytes, nor read an encrypted entry's bytes, whose name and comment it reads, nor read any other archive format: tar, gzip and 7z files are raw bytes to `Files`, as they were. `Files` is unchanged: it still reads a zip archive as raw bytes, and its doc points to `Zip`.

### Fixed
* canary: a line a check gives holds no run of 16 bytes or more of a planted value or of any of its encodings, where before only whole values and encodings were replaced by the value's name. A place where one value runs on into another, the first ending as the second starts, is now shown as <a><b>, where 17 bytes of the second stayed in the line; and a file whose name starts with 24 bytes of a value is shown with those bytes as <name>. An encoding under 16 bytes, which no run is drawn from, as the UTF-16 of six characters of 3 bytes each is 12, is still replaced whole, as v0.6.0 replaced every whole encoding.
* canary: Files reads the target of each symbolic link under the folder as text, the place "<path> (target)", so a program that points a link at a planted value, as with os.Symlink(token, "current"), is caught, and the target of each Windows junction the same way. Of any other entry that is no file or folder it reads the target if it has one, and nothing more than its path if not. It still follows no link or junction: it reads the link, not what the target names. Own's doc says a value drawn at random each run can fall to its quarter rule, one digit over a quarter of 32 random hex characters in about one draw in 574, and that a test should plant a fixed value or one New makes.

### For a v0.5.0 caller

### Added
* canary: a test plants fake secrets with New, or a value of its own with Own, hands them to the program under test, and checks with Files, Reader, Bytes and Value that none reached a file under a folder (a SQLite file and its -wal and -journal read as raw bytes, with no driver), a captured stream or the text of a returned value. Each value is looked for as it is, as hex in both cases, as base64 and URL-safe base64 at each of the three alignments, as percent-encoding exactly as Go's url.QueryEscape and url.PathEscape write it, as UTF-16 in both byte orders, and as its bytes in decimal, the way fmt's %v prints a []byte or a [N]byte, so a key held as the value's own bytes is found in a returned value and in a log line made with %v. Bytes a program decodes from the value it was handed, base64 or hex text, are another value: they are found only when planted too, with Own, beside the text. A value of Own's with punctuation, escaped by an escaper with another safe set, is not found. Files also searches the path of each file, folder and link below the folder: a value in a name is a hit at InPath. A hit fails the test naming the value's name, the check, the place, the byte offset and the encoding, and canary never prints a value: every line that names a place or an error holding one, a path among them, shows it as <name>. Files follows no link and reads no FIFO, socket or device, a file it cannot read fails the test, and a check on a Set with no value planted stops the test. Its limits: a value compressed or encrypted (gzip, a zip archive), or written in an encoding the list does not name, base32 among them, is not seen; a value split across a SQLite overflow page boundary is not found, as SQLite moves the tail of a long record onto overflow pages with a 4-byte page number in between; process memory, the network and any file outside the folders a test names are not checked; and of a regular file Files reads the bytes and the path alone, not its extended attributes (macOS, Linux) or a Windows alternate data stream. canary is 542 non-test Go lines, and the size ceiling rises by 542.
* cmd/apigate: given -before-head, the API check at a tagged head compares against the newest earlier tag: check 2's base is the newest tag that is an ancestor of the head and does not point at it, so the run at v0.2.0 holds the breaks since v0.1.0, and a head whose only tags are its own holds no break, as with no tag. The flag is off by default, and without it the check reads as before, from the newest tag on or below the head.

### Changed
* cmd/apigate: check 2 reads a module in a folder whose go.mod at the base requires the repository's root through a workspace of the base's own, written from the base's go.mod files: the base's root and the module, the root at the version the module requires replaced by the base's root. ### For a v0.3.1 caller

Nothing changes for a test that calls neither new name, but where it gave an option to a call that ignored it: every other name gives what it gave, and `Isolate` and `Build` given a `Before`, or `Build` a `RerunEnv`, now refuse it, as Fixed says. A test of an upgrade can build the earlier release with `BuildAt` beside today's with `Build`. A suite that must not reach the network can pass `NoNetwork` to `Main`; on a system where the guard cannot be set, such as Windows, `Main` then fails the run unless the caller names that system.

### Added
* `BuildAt(t, ref, pkg)` builds a program as it was at an earlier tag, branch or commit of the repository the test runs in, for upgrade tests that run an old release beside the current one. It takes `Build`'s arguments in the same order, adds the ref, and returns the same `*Binary`, so `X` stamps, `Env` and `Run` work as before. It reads the old tree raw, with `git ls-tree` and `git cat-file`, into the test's temp folder, so no filter or attribute applies: a smudge filter, Git LFS's among them, never runs, an LFS file stays its pointer file, line endings stay as committed, and a file marked `export-ignore` is there. Every git it runs is given `GIT_NO_LAZY_FETCH=1`, so a partial clone that lacks the old tree fails the build, saying the clone is partial, and nothing is fetched; that needs git 2.45 or later. It builds the tree with `GOWORK=off`, so that tree's own `go.mod` and `go.sum` decide its modules and no `go.work` near it does; it adds no worktree, checks nothing out and leaves `.git` as it was. Two refs that name one commit build once. Given `NoNetwork`, a `Before` or a `RerunEnv`, which only `Main` acts on, it fails the test, naming the option. A ref or package that starts with `-`, a ref that names no commit, and a package outside the repository fail the test, naming the ref; they never skip it. Under `GoOffline` a module the old tree needs that the module cache lacks fails the build, naming the module.
* `NoNetwork(unguardedOn ...string)`, an option of `Main` alone, holds the test process and every process it starts to loopback: a connection to any address that is not loopback, or on macOS one of the host's own, fails with an error that names the address, and loopback, `httptest` included, works. `Isolate`, `Build` and `BuildAt` refuse it, naming it, as they run no `Before` and so would set no guard: `Isolate` returns an error and changes nothing. On macOS it uses the system sandbox, by `sandbox_init` on the test process itself; on Linux it reruns the tests in a user and network namespace of their own, where only loopback is up. On Linux only the interfaces that are up count, so a tunnel interface a host leaves down in a new network namespace, such as `tunl0` or `sit0`, does not. The guard's marker stays in the tests' environment once the probe passes, so a fuzz worker, or a helper child a test starts as the test binary with its environment, stays inside the guard. Before any test runs, a probe proves the guard: a connect to a documentation address must fail, and one to a listener on 127.0.0.1 must succeed. Where the guard cannot be set, `Main` returns 1 with an error naming the system and the reason, and no test runs, unless the caller names that system in `unguardedOn`; then `Main` writes one line saying the tests run with the network open, and runs them. The guard is tested on macOS arm64, and on Linux amd64 in CI, where the workflow lifts Ubuntu's `kernel.apparmor_restrict_unprivileged_userns`; on macOS amd64 it is built and vetted only. Windows, and every system but macOS and Linux, refuses it: Windows gives an unprivileged process no way to refuse outbound connections and keep loopback. A Linux host that refuses an unprivileged user namespace, and a macOS test process already inside a sandbox, refuse it too. On Linux a run in the guard's namespace that sees an interface up that is not loopback refuses, naming it, and one that cannot read which network namespace it runs in refuses, naming the link. Run as uid 0 on Linux, the tests hold every capability of the nested user namespace and none over the network namespace, and `NoNetwork` goes before `contain.Contain`: as uid 0, a refusal of the namespace inside contain's containment says to put `NoNetwork` first, and one outside it names a container's seccomp profile, which refuses a new user namespace. It does not make a test go red where the code under test swallows the refused connection's error. On macOS the sandbox counts each of the host's own addresses as localhost, so a connect to one is allowed, and a service the host runs on 0.0.0.0 is reachable through it, though no packet leaves the machine. A daemon a test reaches over a Unix socket, such as Docker's, or on macOS a mach service, connects for itself, outside the guard. On Linux a program a test starts that is not Go may look a name up through the C library's resolver, by nscd or systemd-resolved, and so carry the name out, though its connections still fail.

### Fixed
* Isolate and Build refuse a Before, which only Main runs, a containment such as contain's Contain among them, and Build refuses a RerunEnv, which only a Rerun calls: each was ignored, with nothing said, so a containment given to Isolate or Build held neither the tests nor the binary. Isolate returns an error and isolates nothing, and the Binary runs nothing and gives the refusal on Stderr; the refusal names the function and the option, and says to give it to Main.

## v0.3.0 - 2026-11-22
### Added
* `Interrupted(ctx)` gives a child of `RerunInterrupted` a context that ends at the interrupt, and its stop. It installs the handler and only then writes `Ready`'s line, so the parent's interrupt never comes before the handler and ends the child by the default action. Outside a child of `Rerun` it returns `ctx` and a stop that does nothing, installs no handler and writes nothing. Its error is `Ready`'s, and then it leaves no handler. `Ready` stays for a child that catches more than the interrupt.
### Fixed
* `cmd/apigate` refuses a name `api/marks.txt` lists whose `go doc` prints a line holding `Experimental`, and names the `api/marks.txt` line and that doc line. Listing a name marks it as not experimental, so the doc and the list disagreed, and v0.2.0's gate passed it.

### Known limitations
* Added 2026-11-22, after the tag: on macOS the temp folder `Main` and `Isolate` make, and so `t.TempDir`, `os.TempDir`, `TMPDIR`, `HOME`, `HoldRead`'s path and `Binary.Path`, sits behind the `/var` -> `/private/var` link and is named as made, under `/var/folders`, while a path read back by `filepath.EvalSymlinks` or `os.Getwd` is under `/private/var/folders`; `ShortDir`'s `/tmp` reads back as `/private/tmp` the same way. The two spellings differ as strings, so a test that compares a path it was given with one read back resolves its own with `filepath.EvalSymlinks` first. Neither v0.2.0's notes nor v0.3.0's said so. The kit keeps answering the spelling Go's `t.TempDir` and `os.MkdirTemp` give, and each of those calls' docs now says which spelling it answers.

## v0.1.0 - 2026-11-21
### Added
* testkit, the test helpers the birdtable libraries share, as a module of its own. It was go-proc's `testenv` package, and go-proc v0.12.0 drops that package and takes testkit instead.
* `Main` runs a package's tests in a folder testkit makes. The tests keep only the environment names testkit lists, and the home variables, `t.TempDir` and git's configuration point into that folder. A child started through `Clean`, or with `Main`'s environment, sees none of the person's home, git or tool settings, go env file, or a token or a hook's variables the run was started with.
* Checks a test calls: `NoLeaks` fails a run that leaks a goroutine. `NoOpenFiles` reports each file and folder still open under the test's folder on Linux and macOS. On Windows it reports nothing, and the removal of the test's folder is the check there.
* Helpers: `GoOffline`, an option of `Main`, makes every go a test starts fetch no module and no toolchain. `GitPath` gives the host's git as an absolute path. `Link` and `Links` skip with `NoLinks` where the system refuses a link. `Rerun` runs a test again in a child that ends by itself if its parent is gone.
* `testkit/fake`: a stand-in program a test places and starts as a child, which does its steps the same on every system.
* `testkit/contain`, a module of its own, tagged `contain/v0.1.0`, which runs a package's tests contained. On Linux they run in their own user and PID namespaces, as a child of an init that reaps what they orphan, holding no capability in any set, except the mount capability of that namespace where `ContainMounts` keeps it. On Windows they run in a Job Object that ends their tree when it closes. Elsewhere, and where the system refuses, `Contained` skips a test with the reason.
* Requirements: the root module needs the standard library alone. `contain` requires `kernel.org/pub/linux/libs/security/libcap/cap` and `psx` v1.2.78, and testkit v0.1.0.
