## v0.4.0 - 2026-11-26

Two names are added to the root module: `BuildAt` and `NoNetwork`. No name is removed or moved, and no signature changes: the API check finds no break since v0.3.1. Every name added is experimental, as every name of the module is. The root still imports the standard library only, and no require in any go.mod changes. contain stays at contain/v0.1.2 and taskfile at taskfile/v0.1.1: nothing in either module has changed since those tags. The tagged tree is 5,992 non-test Go lines outside `internal/` (`task size`), at its ceiling of 5,992, up 758 from v0.3.1's 5,234, all in the root: 211 for `BuildAt` and 547 for `NoNetwork`. The full release checks ran on macOS (arm64) at the tagged commit; vet and the tests, with the race detector, ran on Linux, macOS and Windows at the tagged commit in CI. No full release checks ran on Linux or Windows for this release.

### For a v0.3.1 caller

Nothing changes for a test that calls neither new name: every other name gives what it gave. A test of an upgrade can build the earlier release with `BuildAt` beside today's with `Build`. A suite that must not reach the network can pass `NoNetwork` to `Main`; on a system where the guard cannot be set, such as Windows, `Main` then fails the run unless the caller names that system.

### Added
* `BuildAt(t, ref, pkg)` builds a program as it was at an earlier tag, branch or commit of the repository the test runs in, for upgrade tests that run an old release beside the current one. It takes `Build`'s arguments in the same order, adds the ref, and returns the same `*Binary`, so `X` stamps, `Env` and `Run` work as before. It reads the old tree with `git archive` into the test's temp folder and builds it with `GOWORK=off`, so that tree's own `go.mod` and `go.sum` decide its modules and no `go.work` near it does; it adds no worktree, checks nothing out and leaves `.git` as it was. Two refs that name one commit build once. A ref or package that starts with `-`, a ref that names no commit, and a package outside the repository fail the test, naming the ref; they never skip it. Under `GoOffline` a module the old tree needs that the module cache lacks fails the build, naming the module.
* `NoNetwork(unguardedOn ...string)`, an option of `Main`, holds the test process and every process it starts to loopback: a connection to any address that is not loopback, or on macOS one of the host's own, fails with an error that names the address, and loopback, `httptest` included, works. On macOS it uses the system sandbox, by `sandbox_init` on the test process itself; on Linux it reruns the tests in a user and network namespace of their own, where only loopback is up. Before any test runs, a probe proves the guard: a connect to a documentation address must fail, and one to a listener on 127.0.0.1 must succeed. Where the guard cannot be set, `Main` returns 1 with an error naming the system and the reason, and no test runs, unless the caller names that system in `unguardedOn`; then `Main` writes one line saying the tests run with the network open, and runs them. The guard is tested on macOS arm64, and on Linux amd64 in CI, where the workflow lifts Ubuntu's `kernel.apparmor_restrict_unprivileged_userns`; on macOS amd64 it is built and vetted only. Windows, and every system but macOS and Linux, refuses it: Windows gives an unprivileged process no way to refuse outbound connections and keep loopback. A Linux host that refuses an unprivileged user namespace, and a macOS test process already inside a sandbox, refuse it too. It does not make a test go red where the code under test swallows the refused connection's error. On macOS the sandbox counts each of the host's own addresses as localhost, so a connect to one is allowed, and a service the host runs on 0.0.0.0 is reachable through it, though no packet leaves the machine. A daemon a test reaches over a Unix socket, such as Docker's, or on macOS a mach service, connects for itself, outside the guard. On Linux a program a test starts that is not Go may look a name up through the C library's resolver, by nscd or systemd-resolved, and so carry the name out, though its connections still fail.
